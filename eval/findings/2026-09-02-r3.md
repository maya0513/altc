# 言語・project統合評価所見（2026-09-02 r3）

array/slice、extern object/layout/callback、複数moduleをwritabilityとrepair corpusへ追加し、[telemetry project](../../examples/telemetry_pipeline/README.md)を実際のC static libraryと一緒に全CLI commandへ通した。

## 解決した所見

- P0: import先のannotationなしexternがmodule内部名をC symbolとして要求した。最小probeは`import memory;`先で`stdlib.h`の`malloc`を宣言する2 file project。元C spellingの保存を実装し、project unit testとtelemetry integration testへ回帰化した。
- P1: moduleをまたぐmemory summaryのspanが合成source offsetのままだった。最小probeはrootからmemory eventを持つ公開関数を呼ぶ2 file project。eventへfileを追加してlocal spanへ戻し、JSON/human表示を修正した。
- P2: callbackに`raise`を付けたとき、本質的な`ALTC3214`に派生診断が重なる。[callback repair](../repair/callback-contract/)で現在挙動を固定し、診断抑制を継続課題として[実装監査](../../docs/implementation-audit.md)へ記録した。

arrayの既知OOBとmodule privacyは、それぞれ`ALTC3053`と`ALTC3404`のhelpから一回の局所編集でfixed sourceへ収束した。extern layout mismatchはglobal constness、field型、enum spelling、callback signatureを別々のRed testで`ALTC6101`へ固定した。
