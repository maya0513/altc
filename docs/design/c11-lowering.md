# C11 lowering設計

この文書は非規範的です。規範的な意味は[Draft仕様](../spec/README.md)、実際に読み比べる例は[対照例](../examples/README.md)を参照してください。

ここで示す変換は実装可能性を説明するものであり、compilerは同じ意味、observable operation、公開ABIを満たす別のC11を生成できます。内部名、helper、temporary、label、control structure、optimization、translation unit配置をこの文書へ固定してはなりません。通常型のlayoutは処理系が選び文書化するimplementation-defined事項であり、単なる非規範的な出力差ではありません。

## 型表現

固定幅整数には`<stdint.h>`、`usize`と`isize`には`<stddef.h>`、`bool`には`<stdbool.h>`または`_Bool`を使えます。`char`はvalid Unicode scalarを保持できる32 bit整数として表現できます。

`str`とsliceはpointerとlengthのstructへloweringできます。通常の内部layoutはimplementation-definedですが、選択したsizeとalignmentを`sizeof`、`alignof`、`emit-c`から観測可能にします。同じ値をcopyしてもdataをcopyしないこと、操作が暗黙allocationを行わないことを維持します。

nullable pointerはC pointerのnull valueを使い、non-null pointerと同じmachine wordにできます。altc側でnon-nullへrefineした後は追加tagを持ちません。

通常enumはtagとpayload unionへ変換できます。`@repr(C)` enumとstructは対象C compilerにlayoutを委ね、生成headerとsourceで同じ宣言を共有します。

## 評価順の保存

C function argumentやoperator operandの評価順へ依存せず、source semanticsで順序が定められたsubexpressionを左から右へtemporaryまたはstatementとしてloweringします。effect集合やmemory access summaryが空であることだけを根拠にcallを並べ替えてはなりません。callを含まず、順序差が値、終了性、undefined behaviorの有無へ影響しないと証明できる式だけを直接C expressionへまとめられます。

block式と`if`式はresult temporaryを作り、各branchで代入した後に使用できます。C compiler extensionのstatement expressionはC11ではないため標準backendでは使いません。

## Operator

通常operatorは対応C operatorへ変換します。wrapping signed演算はunsigned演算またはcompilerが保証できる等価表現を使い、C signed overflowへ依存しません。saturatingとchecked演算はcompare、widening operation、compiler builtin、standard Cの組合せからtargetに適した形を選べます。

compound assignmentは複雑な左辺を一度だけ評価するtemporaryを作ります。

## Loop

`while`とC風`for`は対応するC loopへ直接変換できます。range-forは対象pointerとlengthを一度取得し、`size_t` indexのC loopへ変換します。この形なら、意味上同等な手書きの添字loopに対する追加のruntime costはありません。

値bindingは各iterationでelementをby-value取得する意味です。optimizerが不要なcopyを除去することはできますが、pointer aliasへ意味を変更してはなりません。

## Match

payloadなしenumとinteger literalの`match`は`switch`へ変換できます。payload付きenumはtagの`switch`とpayload fieldの取出しに分けます。armが値を返す場合はresult temporaryを使います。

exhaustivenessはaltc type checkerで保証し、生成Cの`default`はunreachable marker、defensive abort、または省略から選べます。公開動作を変えない限り非規範的です。

## `defer`

scopeごとのdefer listをHIRで保持し、通常fallthroughとすべてのexit edgeへ逆順のcleanupを挿入します。defer bodyは登録位置では評価せず、退出位置でその時点のlocal値を使ってloweringします。Cではcleanup statementの複製またはlabelと`goto`を使えます。

runtime cleanup stackは不要です。return valueとraised errorはcleanup前にtemporaryへ保存し、cleanup後に元のexitを継続します。

## Effectとmemory access summary

`alloc`と`free` annotationは原則としてruntime値を生成しません。type/effect checkerがcompile-timeに検査し、C call自体は通常のcallになります。

effect annotationをdebug metadataやcommentへ出力できますが、program semanticsは変えません。

memory access summaryもcompile-time metadataであり、専用のruntime checkやwrapperを生成しません。source operationは通常のC load、store、callへloweringし、必要ならsummary categoryとsource spanをside tableやdebug commentへ出力できます。summaryは最適化許可の契約ではありません。

## Typed `raise`

raising functionはsuccess/error tagを返すstruct、status returnとout pointer、internal continuationなどへ変換できます。postfix `?`を持つcall siteはstatusを検査し、errorならdefer cleanupを通って最も近いhandlerまたはcallerへ伝播します。`?`のない通常callへ暗黙のstatus branchを挿入してはなりません。

内部表現は自由ですが、専用exception runtime、stack unwinding、暗黙allocationを導入できません。`export "C"` functionだけは仕様で定めた`int32_t` statusとout parameter ABIを使います。

## Generic、trait、method

generic functionとtypeは使用された具体型ごとにC declarationを生成します。trait callは選択済みimplへのstatic callになります。methodはreceiverを第1argumentへ移します。

symbol nameへtype情報のhashやescape済みnameを含められます。内部symbolに言語名の接頭辞を付ける必要はなく、衝突を避けられる任意のmanglingを選べます。同じinstantiationのdeduplication、inline、link-time optimizationは許されます。

## Moduleとheader

一module一translation unitは理解しやすいbaselineですが必須ではありません。複数moduleをまとめる、generic instantiationを専用unitへ置くなどの選択ができます。

altc内`pub`用のprivate headerと、`export "C"`用のpublic headerを分けられます。public headerだけが規範ABIを表します。

extern宣言がある場合は、通常のC sourceとは別にFFI検証用translation unitを生成できます。これは元headerをincludeし、`_Static_assert`、`_Generic`、`_Alignof`、`offsetof`などで手書きcontractを照合します。検証用symbolやexpressionをprogram artifactへlinkしてはなりません。

executableでは`@entry` functionを呼び出す`int main(void)` wrapperを一つ生成します。entrypointの内部C名、wrapperとの同一化は非規範的ですが、altc側へCの`argc`や`argv`を暗黙に構築して渡してはなりません。

## Commentとsource位置

commentを最も近い宣言・statement・expressionへattachし、lowering後の対応nodeの前後へ出力します。一つの式が複数statementになる場合、commentを一度だけ最も意味の近い位置へ置きます。

`#line` directiveでC compilerとdebuggerをaltc file/lineへ戻します。細かなcolumnと複数temporaryの対応にはside tableを併用できます。外部へ保存する生成C sourceとheaderの先頭には`/* Generated by altc. Do not edit. */`を一度だけ置きます。由来表示のために各内部identifierへ言語名の接頭辞を反復する必要はありません。生成Cの空白とcomment columnは再現対象ではありません。

## 可読性と最適化

debug/inspect用のCは安定したindentation、型名、source commentを優先できます。release用のCは同じ意味を維持してtemporary削減やfunction統合を行えます。どのmodeでもaltc整数演算、評価順、effect、memory operation、errorの意味を変えてはなりません。
