# 非規範的なaltc/C11対照例

> このCコードは、altcの意味とコストモデルを説明するために推定した非規範的なlowering例です。実装はこの出力形式、内部名、helper、制御構造、最適化、コメント位置、翻訳単位構成を模倣してはならず、Draft規範仕様を満たす別のC11生成を選べます。

このディレクトリは、altcのsourceと、それをC11で実現する一例を機能別に並べます。掲載Cはcompiler snapshotでも`.expected.c`でもありません。実装の正しさはtext一致ではなく、[Draft仕様](../spec/README.md)の意味、observable operation、明示公開ABI、コストmodelへの適合で判断します。

## 読み方

各pageは次の順で構成します。

1. 関連する規範仕様
2. 推定altc source
3. 取り得る自己完結C11 lowering
4. 固定される意味と、実装へ委ねる形の説明

生成物として示す各C sourceとheaderは、先頭の`/* Generated by altc. Do not edit. */`で由来を一度だけ示します。内部identifierに言語名の接頭辞は付けず、読みやすい説明用の名前を使います。実装は別名、別layout、別control flowを選べます。`export "C"`、`@repr(C)`、typed `raise`の公開ABIとして仕様が明記した箇所だけは例ではなく仕様側の契約に従います。

## 検証方針

単一C blockは`cc -std=c11 -pedantic-errors -fsyntax-only`で検査できる形にします。複数file例はpageに示したfile名で分割し、compile、link、expected outputまで確認します。

将来compilerが実装されても、掲載Cとのtext diffをtestにしてはなりません。altc blockをcompile/runするdoc testへ移行し、生成Cはstrict C11、公開ABI、実行結果、allocationやdispatchの有無を構造的に検証します。
