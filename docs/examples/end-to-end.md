# End-to-end統合例

> このCコードは、altcの意味とコストモデルを説明するために推定した非規範的なlowering例です。実装はこの出力形式、内部名、helper、制御構造、最適化、コメント位置、翻訳単位構成を模倣してはならず、Draft規範仕様を満たす別のC11生成を選べます。

この例は複数module、C allocation、typed `raise`、`?`による明示伝播、`defer`、generic monomorphization、`Option`のmatch、C ABI公開を一つにまとめます。

関連仕様：[module](../spec/declarations-and-modules.md#module)、[effectとerror](../spec/memory-effects-and-errors.md)、[generic](../spec/generics-traits-and-methods.md)、[C公開](../spec/c-interop.md#c-abi公開とheader生成)

## altc module

```altc
// file: src/buffer.altc
extern "C" from <stdlib.h> {
  fn malloc(size: usize) -> ?*mut unit with { alloc };
  fn free(pointer: *mut unit) with { free };
}

@repr(C)
pub enum ProcessError {
  Allocation,
  Empty,
  Invalid,
}

pub struct Buffer {
  pub data: *mut u8,
  pub len: usize,
}

pub fn identity[T](value: T) -> T {
  value
}

pub fn make(size: usize) -> Buffer
    with { alloc, raise[ProcessError] } {
  match malloc(size) {
    nonnull(raw) => Buffer {
      data: ptr_cast[u8](raw),
      len: size,
    },
    null => raise ProcessError::Allocation,
  }
}

pub fn release(value: Buffer) with { free } {
  free(ptr_cast[unit](value.data));
}

pub fn first(value: *const Buffer) -> u8
    with { raise[ProcessError] } {
  if value->len == 0 {
    raise ProcessError::Empty;
  }
  let byte: u8 = *value->data;
  if byte > 9u8 {
    raise ProcessError::Invalid;
  }
  byte
}
```

```altc
// file: src/api.altc
import buffer;

@c_name("process_byte")
export "C" fn process(input: u8) -> i32
    with { alloc, free, raise[buffer::ProcessError] } {
  let owned = buffer::make(1)?;
  defer {
    buffer::release(owned);
  }

  *owned.data = input;
  let byte = buffer::first(&owned)?;
  let optional: Option[u8] = if byte == 0u8 {
    Option::None
  } else {
    Option::Some(byte)
  };

  match optional {
    Option::Some(value) => buffer::identity[i32](value as i32),
    Option::None => 0,
  }
}
```

## 取り得るbuffer moduleのC

```c
/* Generated by altc. Do not edit. */
/* buffer.c */
#include "internal.h"
#include <stdlib.h>

int32_t buffer_make(
    size_t size,
    Buffer *out_value,
    ProcessError *out_error) {
  uint8_t *data = (uint8_t *)malloc(size);
  if (data == NULL) {
    *out_error = ProcessError_Allocation;
    return 1;
  }
  out_value->data = data;
  out_value->len = size;
  return 0;
}

void buffer_release(Buffer value) {
  free(value.data);
}

int32_t buffer_first(
    const Buffer *value,
    uint8_t *out_value,
    ProcessError *out_error) {
  if (value->len == 0u) {
    *out_error = ProcessError_Empty;
    return 1;
  }
  uint8_t byte = *value->data;
  if (byte > UINT8_C(9)) {
    *out_error = ProcessError_Invalid;
    return 1;
  }
  *out_value = byte;
  return 0;
}
```

## 取り得るapi moduleのC

```c
/* Generated by altc. Do not edit. */
/* api.c */
#include "internal.h"

static int32_t identity_i32(int32_t value) {
  return value;
}

int32_t process_byte(
    uint8_t input,
    int32_t *out_value,
    ProcessError *out_error) {
  Buffer owned;
  int32_t status = buffer_make(1u, &owned, out_error);
  if (status != 0) {
    return 1;
  }

  *owned.data = input;
  uint8_t byte = UINT8_C(0);
  status = buffer_first(&owned, &byte, out_error);
  if (status != 0) {
    buffer_release(owned);
    return 1;
  }

  if (byte == UINT8_C(0)) {
    *out_value = INT32_C(0);
  } else {
    *out_value = identity_i32((int32_t)byte);
  }

  buffer_release(owned);
  return 0;
}
```

## C client

```c
/* client.c */
#include "api.h"

int main(void) {
  int32_t value = INT32_C(0);
  ProcessError error = ProcessError_Allocation;

  int32_t ok = process_byte(UINT8_C(7), &value, &error);
  if (ok != 0 || value != INT32_C(7)) {
    return 1;
  }

  int32_t invalid = process_byte(UINT8_C(42), &value, &error);
  if (invalid != 1 || error != ProcessError_Invalid) {
    return 2;
  }
  return 0;
}
```

## Compileと実行

```sh
cc -std=c11 -pedantic-errors -c buffer.c api.c client.c
cc buffer.o api.o client.o -o end-to-end
./end-to-end
```

## 対応の要点

- `malloc` / `free`は元のC libraryを直接使い、専用allocatorやGCを追加しません。
- `Buffer`はpointerを所有する規約で使っていますが、言語上は通常のcopy可能なstructです。effectはcopy、double free、leakを防止しません。
- `buffer::first`のreadと`api::process`のwriteはmemory effectを要求せず、memory access summaryの`indirect-read`と`indirect-write`として推論されます。
- `buffer::make(1)?`と`buffer::first(&owned)?`は、同じ`ProcessError`を`api::process`へ伝播する位置を明示します。
- successとerrorの両方でdefer相当の`buffer_release`が実行されます。
- `identity[i32]`は一つのstatic specializationです。runtime generic情報はありません。
- `Option[u8]`はlocal control flowへ最適化できます。必ずC structを作る必要はありません。
- public headerと`process_byte` ABIは規範仕様に従います。内部header、module分割、cleanupの複製は非規範的です。
