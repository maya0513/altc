# Tooling

> このCコードは、altcの意味とコストモデルを説明するために推定した非規範的なlowering例です。実装はこの出力形式、内部名、helper、制御構造、最適化、コメント位置、翻訳単位構成を模倣してはならず、Draft規範仕様を満たす別のC11生成を選べます。

関連仕様：[tooling](../spec/tooling.md)、[doc comment](../spec/lexical-structure.md#空白とコメント)、[test block](../spec/declarations-and-modules.md#test-block)

## altc

外側のMarkdown fenceとdoc comment内のfenceを区別するため、この例だけtilde fenceを使います。

~~~~altc
/// 2つの整数を加算する。
///
/// ```altc
/// assert_eq(add(20, 22), 42);
/// ```
pub fn add(left: i32, right: i32) -> i32 {
  // この通常commentは対応する生成Cの近くへ残せる。
  left + right
}

test "positive values" {
  assert_eq(add(20, 22), 42);
}

test "negative values" {
  assert_eq(add(-20, -22), -42);
}
~~~~

## CLIでの流れ

```sh
altc check src/math.altc
altc check --ffi src/math.altc
altc fmt src/math.altc
altc test src/math.altc
altc doc src/math.altc
altc emit-c src/math.altc --output-dir build/generated
```

## 対応の要点

- test harnessはtest artifactだけに存在し、通常libraryへentrypointを追加しません。
- `#line`によってC compilerとdebuggerのlineをaltcへ戻せます。directiveの粒度は非規範的です。
- commentは一度だけ意味の近いnodeへ配置します。元columnと空白は再現しません。
- doc testはaltc sourceとしてcompileしますが、このpageの推定Cはgolden testにしません。
