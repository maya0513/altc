# ModuleとC連携

> このCコードは、altcの意味とコストモデルを説明するために推定した非規範的なlowering例です。実装はこの出力形式、内部名、helper、制御構造、最適化、コメント位置、翻訳単位構成を模倣してはならず、Draft規範仕様を満たす別のC11生成を選べます。

関連仕様：[宣言とmodule](../spec/declarations-and-modules.md)、[C連携](../spec/c-interop.md)

## 入力C header

```h
/* native_scale.h */
#ifndef NATIVE_SCALE_H
#define NATIVE_SCALE_H

#include <stdint.h>

int32_t native_scale(int32_t value);

#endif
```

## altc module

```altc
// file: src/math.altc
extern "C" from "native_scale.h" {
  fn native_scale(value: i32) -> i32;
}

pub fn scaled(value: i32) -> i32 {
  native_scale(value)
}
```

```altc
// file: src/api.altc
import math;

@repr(C)
pub struct Pair {
  first: i32,
  second: i32,
}

@c_name("project_sum_scaled")
export "C" fn sum_scaled(pair: Pair) -> i32 {
  math::scaled(pair.first) + math::scaled(pair.second)
}
```

`math::scaled`はaltc module間の`pub`であり、C ABI公開ではありません。`sum_scaled`だけが、指定したC名`project_sum_scaled`で生成public headerへ現れます。

## 取り得る生成header

```h
/* Generated by altc. Do not edit. */
/* api.h */
#ifndef API_H_INCLUDED
#define API_H_INCLUDED

#include <stdint.h>

typedef struct Pair {
  int32_t first;
  int32_t second;
} Pair;

int32_t project_sum_scaled(Pair pair);

#endif
```

## 取り得る生成C

```c
/* Generated by altc. Do not edit. */
/* modules.c */
#include "api.h"
#include "native_scale.h"

static int32_t math_scaled(int32_t value) {
  return native_scale(value);
}

int32_t project_sum_scaled(Pair pair) {
  int32_t first = math_scaled(pair.first);
  int32_t second = math_scaled(pair.second);
  return first + second;
}
```

## C側の実装とcaller

```c
/* native_scale.c */
#include "native_scale.h"

int32_t native_scale(int32_t value) {
  return value * INT32_C(2);
}
```

```c
/* client.c */
#include "api.h"

int main(void) {
  Pair pair = { INT32_C(3), INT32_C(4) };
  return project_sum_scaled(pair) == INT32_C(14) ? 0 : 1;
}
```

上のC fileは次のように独立compileとlinkができます。

```sh
cc -std=c11 -pedantic-errors -c modules.c native_scale.c client.c
cc modules.o native_scale.o client.o -o module-example
./module-example
```

## 取り得るFFI検証用C

通常artifactとは別のtranslation unitで、手書きした`native_scale`宣言と元headerを照合できます。

```c
/* Generated by altc. Do not edit. */
#include "native_scale.h"
#include <stdint.h>

typedef int32_t (*ExpectedNativeScale)(int32_t);

_Static_assert(
    _Generic(&native_scale, ExpectedNativeScale: 1, default: 0),
    "altc extern declaration for native_scale does not match native_scale.h");
```

この検証用Cはcompileだけを行い、programへlinkしません。`altc build`と`altc test`は常に検証し、frontendだけの`altc check`では`--ffi`を付けた場合に実行します。

## 対応の要点

- 元の`native_scale.h`を生成Cでもincludeし、手書きextern宣言との不一致をC compilerにも検査させます。
- header includeだけに依存せず、検証用translation unitでfunction pointer型を完全一致させます。
- `pub` functionを同じC fileの`static`へ置く形は一例で、translation unitを分けても構いません。
- `Pair`の`@repr(C)` field順と`project_sum_scaled`名は公開ABIです。
- include guard、内部名、moduleをまとめるか分けるかは非規範的です。
